# Round 4：Shared DiT 融合 LeFlow 的探索性实验

  ## 1. 目标与实验边界

  本轮与 Round 3 的 online train 并行开展，验证 shared DiT 增加 latent planner（D）和 IDM（E）后的可行性，以及 LeFlow 式规划的性能与
  效率。

  本轮只训练 A+B+D+E，去掉 R4-AB，以现有 E5/E6 和独立 LeFlow 为参考。不重做 Round 1 的 E0–E6 多训练组消融。

  主要回答：

  1. 能力可行性：同一个 shared DiT 能否学会 D/E，同时保留可用的 A/B 能力？
  2. 候选生成方式：同一模型、同一 B 验证器下，latent 路径经 IDM 转成的动作，是否优于直接生成动作？
  3. 规划权衡：生成后选优与 E6 warm-start CEM 相比，成功率和规划耗时如何变化？

  固定范围：

  - 四任务：Cube、Push-T、Reacher、TwoRoom。
  - 首轮每任务一个训练种子 3072，共4个训练 run。
  - 整个 A+B+D+E 模型从头训练，包括 encoder/projector，不从 E5 续训。
  - A/B 保持 E5 的动作混合、cross-head gradient、legacy token/timestep、192维 shared DiT、parallel_prefix 和 strict_causal 设置。
  - 本轮不加入新 Stage C、latent warm-start CEM、online train，以及容量、token 编码和 attention 搜索。

  现有 E5 与本轮训练的数据划分、部分 batch 设置不同，作为历史参考，不据此独立证明“新增 D/E 监督改善了 A/B”。严格的训练迁移归因留待后
  续匹配对照。

  Round 3、Round 4 使用独立代码快照、训练目录和实验登记表，不互相跟随中间配置或权重变化。默认使用 GPU0 –
  3；不抢占已有任务，当GPU0~3的剩余显存充足时即可发起新任务，以充分利用显存资源。所有 GPU/EGL 操作显式绑定 GPU0–3，禁止使用 GPU4–7。正式延迟测量时对应设备不运行其他工作。


  ## 2. 前置验收、参考模型与评测协议

  ### LeFlow 复现验收

  - 验证起点/目标固定、IDM 动作对齐、action block，以及执行动作与 B 验证动作一致。
  - 确认 reranking 根据动作 rollout 的预测终点评分，而不是生成路径中被固定的目标端点。
  - 审计训练 loss 的实际梯度路径，记录 consistency loss 使用的路径来源及更新模块。
  - 四任务完成新协议开发评测与200-episode参考评测；已有结果通过 cohort、权重、配置和 trace 校验后复用。
  - 新协议结果不要求数值等于论文旧协议结果；实现或协议错误必须先修复。

  四任务复现验收完成后启动正式 R4-ABDE 训练。 此前允许完成实现、CPU检查和接口测试。

  ## 3. Shared D/E 实现与训练设置

  ### 统一模型

  共享一套 encoder/projector 和 DiT blocks，D/E 增加必要的位置参数、模式条件及小型输出头。

   模式    已知条件                  输出
  ━━━━━━  ━━━━━━━━━━━━━━━━━━━━━━━━  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   A       (z_0,z_g)                 动作序列 (a_{0:H-1})
  ──────  ────────────────────────  ──────────────────────────────────────
   B       (z_0,a_{0:H-1})           未来状态 (z_{1:H})
  ──────  ────────────────────────  ──────────────────────────────────────
   D       (z_0,z_g)、噪声           中间状态 (z_{1:H-1})，固定 (z_H=z_g)
  ──────  ────────────────────────  ──────────────────────────────────────
   E       完整状态路径 (z_{0:H})    动作序列 (a_{0:H-1})

  每个动作 token 对应一个 action block。

  具体约定：

  - D：rectified flow，布局为 [z0, zg, noisy interior tokens]。中间 token 双向通信并读取锚点；锚点不读取噪声 token。新增 latent
    velocity head，与 B 的状态预测头分开。

  - E：全路径条件、单次回归。干净状态 token 与 H 个动作 query 输入 shared DiT；动作 query 读取整条路径并相互通信，状态 token 不读取动
    作 query。新增 IDM action head，与 A 的 velocity head 分开。

  - B：保持现有因果约束。验证时只输入当前状态和候选动作，不读取生成路径；目标仅用于外部评分。
  - 新能力显式启用，默认关闭，保持旧 checkpoint 的严格加载行为。

  新增接口：

  - sample_latent_paths(...) → [batch, samples, H+1, latent_dim]。
  - decode_latent_paths(...) → [batch, samples, H, action_block_dim]。
  - train_mode=stage_abde：计算 A/B/D/E 训练目标。
  - best-of-N solver：proposal_source=action|latent，复用现有 World Policy 输出接口。

  Round 4 使用独立入口调用公共训练、评测组件，避免改写 Round 3 的实验逻辑。

  ### 训练预算

  仅训练 R4-ABDE，四任务各1个种子：

  - 10 epochs，固定使用 epoch 10 权重，不选择中间峰值。
  - AdamW，学习率 5e-5、weight decay 1e-3、梯度裁剪 1.0、bf16。
  - 沿用 E5 训练入口的学习率调度，登记解析后的调度参数。
  - 单卡真实 batch=128，accumulate_grad_batches=1。
  - 正式训练前测量完整 A+B+D+E batch128 的显存、吞吐及前向/反向正确性。
  - 若显存不足，先排查多余计算图保留并评估保持训练语义的内存优化；不得静默改成 microbatch32×4。仍无法运行时，记录实测情况后修订配置。
  - 初始化、数据顺序、A/B 噪声、动作混合、D 噪声采用独立且可复现的 RNG 流。
  - 每个 batch 共享一次图像编码，计算各任务 loss，相加后更新一次。记录更新次数、数据暴露量、耗时和 GPU-hours。

  历史核对说明：Cube、Push-T 的现有 E5 配置为 batch128；Reacher、TwoRoom 复用的早期配置为 batch200。核查的 Round 2 实验为单卡
  batch128。因此本轮设置不表述为与所有历史 E5 完全一致。

  不预设梯度累积的原因是：projector 的 BatchNorm 和 SIGReg 依赖 batch 内统计，32×4 不等价于真实 batch128。

  ### 损失与诊断

  $$
  \mathcal L_{\mathrm{ABDE}}
  =\mathcal L_{\mathrm{E5\text{-}AB}}
  +\mathcal L_D+\mathcal L_E.
  $$

  - A/B 与 SIGReg 原有计算保持不变。
  - D 使用 flow matching MSE；噪声插值输入与目标 velocity 中的监督 latent 停止梯度。
  - D 的干净起点/目标条件以及 E 的路径输入保留 encoder 梯度。
  - E 根据真实路径回归对应真实动作，使用逐元素平均 MSE。
  - D/E loss 权重均为1；首轮不加入 consistency、cycle 或 smoothness loss。
  - 开发诊断在 epoch 0、5、10 执行。epoch 0 用于运行检查，epoch 5 不用于换配置或因无提升而提前停止。

  ## 4. 最小消融与推理评测

  ### 必做推理矩阵

  以下模式全部使用同一任务的 R4-ABDE epoch 10 checkpoint，不增加训练 run：

   编号       推理方式                  目的
  ━━━━━━━━━  ━━━━━━━━━━━━━━━━━━━━━━━━  ━━━━━━━━━━━━━━━━━━━━━━━━
   P0         A 直接执行                检查动作生成能力
  ─────────  ────────────────────────  ────────────────────────
   P0-shuf    A shuffled-goal           检查目标依赖
  ─────────  ────────────────────────  ────────────────────────
   P1         B + 随机初始化 CEM        检查动力学规划能力
  ─────────  ────────────────────────  ────────────────────────
   P2         A warm-start CEM          同一模型内的 E6 式基线
  ─────────  ────────────────────────  ────────────────────────
   P3         A best-of-N + B 选优      动作候选对照
  ─────────  ────────────────────────  ────────────────────────
   P4         D→E best-of-N + B 选优    本轮主方法

  P2 与“历史 E5 权重的 E6”分开标记。

  固定设置：

  - P3/P4：N=64、16个 Euler steps。
  - E：单次前向恢复全部动作。
  - P0/P0-shuf：16步；P2 保留现有10步 actor warm-start 设置。
  - 候选批量并行生成、解码和验证，B 使用 parallel-prefix。
  - P3/P4 只进行一次候选集合选优，没有 CEM 迭代。
  - 评分与实际执行采用一致的动作归一化和合法性处理。

  评分定义：

  [
  J_i=\operatorname{MSE}\big(B(z_0,A_i)_H,z_g\big).
  ]

  选择最低分动作候选，按照冻结的 receding-horizon 约定执行。不能使用 D 已固定为目标的生成终点进行评分。

  ### 本轮保留的最小对照

  1. P4 对 P3：主要对照。 同一模型、同一 B、相同候选数与积分步数，比较两种候选生成路线。
  2. P4/P3 对 P2：完整规划方式对照。 比较成功率与耗时；P3/P2 的 actor 积分步数也不同，不把变化单独归因于 CEM。
  3. P2 对 P1：warm-start 对照。 判断新模型中 actor 初始化是否仍然有帮助。
  4. 开发集 P4-first：关闭 B 选优。 每次重规划直接执行第一个 latent 候选，检查 reranking 的作用。闭环状态分叉后，不声称不同策略后续遇
     到相同候选。

  5. 离线 IDM 诊断。 在真实 latent 路径上测 E 的动作误差及 B 对解码动作的重建误差；生成路径误差单独记录，区分 IDM 能力不足与路径难以
     执行。

  P4-first 和离线路径诊断只用于开发，不扩大 final 推理矩阵。

  本轮不做新的 A-only、B-only、A+B、A+B+D、A+B+E、独立 D/E 网络或 detached-gradient 训练组。推理时不调用 D/E，不等于训练时没有 D/E，
  不能用推理切换代替训练任务消融。

  ### 指标与计时

  每任务报告：

  - 成功率、Wilson 区间、episode 配对改善/退化数。
  - 首次成功时间、终点物理距离。
  - A/B/D/E 验证 loss、latent 方差和任务梯度范数。
  - 完整评测耗时，以及规划中的编码、生成、IDM、B 验证和总耗时。
  - 峰值显存、候选数和模型前向次数。

  延迟使用固定开发状态、单环境、相同硬件与精度，预热并同步计时，报告中位数和 P95。P3/P4 候选 batch 固定64。不同任务的物理距离不混合平
  均；原版自回归 LeWM 与本轮并行 B 的速度差，不全部归因于 latent proposal。

  ## 5. 验收、扩展规则与交付

  ### 实现验收

  正式训练前完成：

  - D 起点与终点精确固定，噪声能产生不同内部路径。
  - H个动作与H+1个状态正确对齐。
  - B 不读取目标或生成路径；未来动作不能影响较早的预测。
  - A/B/D/E 梯度进入同一组 DiT；D 监督目标停止梯度；优化器没有重复参数。
  - eval 模式、相同噪声下，批量与逐候选计算数值一致，候选拆批不改变选优结果。
  - 构造生成终点相同、动作后果不同的候选，验证评分来自 B。
  - GPU2 上完成真实 batch128 的训练检查和短程环境 smoke。

  ### 完成与补种子规则

  首轮完成四任务 R4-ABDE 的固定训练预算及主评测。有实现错误先修复；训练合法完成但没有收益时，正常交付负结果。

  补种子决定只使用 epoch 10 开发结果，并在查看本轮 final 结果前冻结。满足以下任一条件，补跑四任务的种子 3073、3074，不自动新增训练消
  融组：

  - 性能信号：P4 相对 P3 或 P2，至少两任务提高5个百分点，且无任务下降超过5个百分点。四任务采用同一个比较对象，不按任务挑较弱基线。
  - 效率信号：P4 相对 P2，四任务均不下降超过2个百分点，且至少两任务完整规划中位延迟降低一半。

  这些门槛仅决定是否扩大探索预算，不代表统计显著。历史 E5/E6 差值单列，不替代同一 checkpoint 的门槛。

  未通过则交付四任务单种子结果；通过则完成三个种子的固定200-episode评测，分别报告种子波动与 episode 配对差异。

  ### 后续研究与交付

  有明确正向信号后，再按需要另立：

  - 匹配 A+B 训练组：验证 D/E 是否改善 A/B。
  - 共享与独立 D/E 对照：验证参数共享的价值。
  - D/E 任务拆分、consistency loss、新 C 或 latent CEM。
  - 与 Round 3 online train 的组合实验。

  本轮交付独立配置、训练与评测入口、模型接口，以及 outputs/round4/ 中的数据清单、配置和权重哈希、开发/final traces、效率数据与逐任务
  报告。

  报告明确区分：能力可行性、同模型推理对照、历史性能参考。单种子探索结果不升级为稳定性能或训练因果结论。
