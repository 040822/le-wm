## 2\. 评测协议与完整矩阵

### 公共评测协议

| 项目 | 冻结值 |
|---|---|
| 任务 | TwoRoom、PushT、Reacher、OGBench-Cube |
| 训练重复 | 每方法每任务一个固定 checkpoint |
| 评测 seeds | `42, 100, 2026, 3407, 1234, 4444` |
| 每 seed | 50 episodes |
| 目标距离 / 执行预算 | 四任务均为 25 / 50 |
| horizon / receding\_horizon / action\_block | 5 / 5 / 5 |
| 环境批量 | 每次评测 50 个环境 |
| 精度 | FP32，关闭 autocast、TF32 和编译优化；成功率与计时使用相同精度开关 |

使用 LeWM 原始起点采样、目标设置和环境成功判据。预先生成四任务×六 seeds 的 **24 份评测样本清单**，所有方法共享。保留原采样允许的同轨迹不同起点及初始成功样本，不引入 Round5 确认集的额外过滤；记录样本重复和跨 seed 重叠情况。

分别固定样本采样、环境和策略的随机种子，禁止通过更换 seed 或重新抽样处理失败。该主表属于公开 benchmark 协议，不作为严格 held-out 泛化实验。

上表的默认模型生成、评分和执行跨度均为 25 个环境步。新增 Reacher 短时域配置只修改评分／执行前缀，见下文；四任务的目标 offset=25 和总执行预算=50 保持一致。所有 baseline，包括第二阶段 Sub-JEPA，均保持评分／执行 25/25。

### CoWM 推理矩阵

所有调用动作生成器的配置均使用 **Euler、step=2**；P1 不调用动作生成器，其生成步数记为“不适用”。

| 协议 | 定义 |
|---|---|
| P0 | 单候选直接执行 |
| P1 | CoWM 动力学上的 CEM |
| P2 | 动作生成结果初始化 CEM |
| P3 | 生成 64 个候选，由 CoWM 评分选择 |
| P0-GF / P0-PO | 单候选生成中引导 / 生成后优化 |
| P2-GF / P2-PO | 引导或优化生成结果，再初始化 CEM |
| P3-GF / P3-PO | 对全部候选引导或优化，再选择 |
| P3-PO-refine | 先从 64 个候选中选择，再优化选中动作 |

四种无引导协议各评测一次；七种引导/优化协议分别运行两套预算：

| 预算 | PO | GF | 步长 / 最大 RMS 偏移 |
|---|---|---|---|
| 轻量 | 2 次更新 | 两个生成步各 1 次更新 | 0\.01 / 0.2 |
| 较大 | 5 次更新 | 两个生成步各 5 次更新 | 0\.01 / 0.2 |

PO/GF 沿用现有更新规则、归一化坐标和偏移约束实现；两档 PO 与 GF 均不宣称计算量相同。轻量档总更新数为 PO2/GF2，较大档为 PO5/GF10；GF 在每个 Euler 步使用局部 reference，PO 使用完整生成动作作为 reference。保存实际 A/B 前向、反向次数与动作位移。

每套共 **18 种 CoWM 配置**，完整运行以下两套动作处理：

- **正式主版本**：P0/P1/P2/P3 及其引导版本均关闭规划内部的额外候选投影，使用 `action_bound_mode=none`，保留环境原生动作处理。
- **候选裁剪测试**：P0/P3 使用 `clip`，P1/P2 使用 `candidate_clip`；在候选评分前投影到真实物理动作边界。P3-PO-refine 在选中动作优化后还必须再次投影，保存最终动作及其投影统计。其余配置相同，不根据测试成绩替换主版本。

裁剪范围由环境物理动作边界转换到模型归一化坐标，不能直接将归一化动作截断为 `[-1,1]`。裁剪测试的 GF/PO 保留既有“未投影代价上的梯度优化，随后合法投影”语义，不能写成每次内层梯度 cost 都对应投影后的动作；本轮不另改梯度目标。RMS 修正约束与物理动作裁剪分别记录。

### Baseline

- **LeWM**：公开 CEM 实现，300 samples × 30 iterations、top-k=30、var\_scale=1；不额外增加候选裁剪。
- **LeFlow**：64 候选、16 个 flow steps，使用配套冻结 LeWM 做 rollout reranking；保留现有实现及其 history 配置。
- **Sub-JEPA（第二阶段）**：已接入的官方四任务权重及其原生 encoder、predictor、history 和动作归一化；CEM 300×30、top-k=30、var\_scale=1，执行／评分 25/25，不额外增加候选裁剪。
- CoWM P1/P2 同样使用 300×30、top-k=30、var\_scale=1；P2 初始化缩放固定为 1。

LeWM 的 300×30 属于公开代码默认配置下的统一重评；原论文 Appendix D 对 PushT 使用最多 30 次迭代、其它任务最多 10 次。论文中准确说明本研究的重评设置，不将所有任务 30 次迭代描述为逐项复刻原论文。

### 新增 Reacher 短时域版本

新增 **CoWM-Selection†**：仍使用 Round4 AB 的同一 checkpoint、5×5 输出、Euler step=2、64 候选。仅 Reacher 改为 `execute_steps=10`、`score_horizon_blocks=2`，即执行／评分 10/10；目标仍为第 25 步图像，生成仍覆盖 25 步，总预算仍为 50 步。其它三个任务复用原 CoWM-Selection 的 25/25 单元。

原 CoWM-Selection 的四任务 25/25 行保留。新行在表注中明确“† 仅 Reacher 使用 10/10，其它任务与原 Selection 相同”，四任务宏平均仍按每 seed 的四任务结果计算；复用单元标记为 alias，不重复评测或声称增加独立样本。该行属于预先声明的部署配置比较，不作为等重规划频率的机制对照。

选 10/10 的准则是：**在已有探索成功数持平时，优先减少规划调用**。原始轨迹提供如下取舍：

| Reacher P3 探索结果 | 10/10 | 5/5 |
|---|---:|---:|
| 成功数 | 50/50 | 50/50 |
| 平均首次成功／执行步数 | 19.16 | 12.80 |
| 平均每 episode 规划次数（推算） | 2.24 | 2.94 |

调用次数按逐 episode 的 `ceil(steps_executed / execute_steps)` 推算，依据固定执行前缀、成功即停止的现有路径；正式实验按事件参与索引直接记录。来源及计算说明见 [二次复查报告](../report/cvpr/cvpr_table1_second_review_20261003.md)。5/5 更早完成环境任务，10/10 的规划调用更少；不能仅凭完整 50 步预算下最多 5 次／10 次调用，认定 10/10 的实际端到端完成时间更短。旧探索计时受共享负载影响，不作为配置选择依据。

正式运行固定 10/10，不根据正式成功率在二者间再选择。本轮不把短时域扩展到其它任务、P0-PO 或 baseline；旧探索成绩不直接填入正式主表。

当前 A 仍生成完整 25 步动作，B 仍生成完整预测后读取第 2 个 block 的评分；短评分不意味着单次推理计算自动缩短到原来的 2/5。正式计时据实测量单次与累计规划成本。

该 Reacher 条件运行主版本与候选裁剪测试两种动作处理，各六 seeds。核心矩阵仍为 **36 种 CoWM 配置 + 2 个 baseline = 38 种配置**、912 单元、45,600 episodes；新增 12 个 Reacher 单元后，共 **924 个独立评测单元、46,200 个实际 episodes**，不含独立计时。新主表行其它三任务的展示值复用核心矩阵，不计入新增工作量。

第二阶段 Sub-JEPA 增加四任务×六 seeds，即 **24 单元、1,200 episodes**。两个阶段合计 **948 个独立评测单元、47,400 个实际 episodes**；独立计时与已有接入 smoke 均不计入此数。

### 实现方式

新增正式实验配置及统一入口，提供“准备资产、列出矩阵、评测、计时、汇总”几个操作。复用现有模型、策略构造和 LeWM 评测公共组件，不直接沿用 Round5 的过滤后评测集及固定输出路径。

正式结果身份包含任务、评测 seed、权重哈希、协议、模型生成跨度、执行／评分跨度、修正预算、裁剪模式和配置哈希。只有身份及完整性全部匹配的已完成单元才允许断点续跑时跳过。

正式配置显式保存各方法的 goal-cache 开关、history 长度／padding、solver batch、candidate batch、proposal chunk 和精度开关。成功率与独立计时使用相同算法实现及冻结设置，环境批量差异明确记录；不得为计时另选候选数、分片参数或精度。

- **示例视频固定为 seed=42 的前两个评测 slot**，每任务、每配置均使用相同选择规则。

输入训练/评测数据集不重复复制；非示例 episode 不保存完整 RGB 视频。已有正式结果不得覆盖或自动清理；重跑写入新的 attempt，保留失败记录和采用原因。归档清单区分“缺失、失败、完成”，避免将缺失结果当作零成功率。

### 独立计时：冻结口径与实施要求

文献依据见 [计时来源说明](../report/cvpr/cvpr_table1_timing_and_scope_20261003.md)，后续修订见 [二次复查报告](../report/cvpr/cvpr_table1_second_review_20261003.md)，实施以本计划为准。LeWM 的 planning-time 图、LeFlow 的整批 evaluation time 和 Sub-JEPA 的成功率评测并非共同的单决策延迟协议；本研究在自己的同卡环境统一重测。以下预热、输入数量与缓存规则是本研究制定的协议，不宣称来自三篇论文的共同规定。

主延迟为 **环境批量 1 的完整重规划 wall-clock 时间**。从原始观测／目标及方法所需 history 已在 CPU 内存中、即将交给策略开始，到策略输出 CPU 上可执行动作结束，计入图像处理、CPU/GPU 数据转换、所有 encoder、生成、rollout 评分、CEM 或动作梯度优化、选择和动作反归一化。排除模型／数据集加载、样本读取、环境 stepping/rendering、视频和文件写入。计时前后执行 CUDA 同步，使用 `time.perf_counter`；不能用 GPU kernel 时间代替该主指标。

具体规则：

1. 同一张空闲 GPU3，串行测所有方法；统一 FP32、关闭 autocast、TF32 与编译，CPU／BLAS 线程数固定为 1，记录 GPU、CPU、软件及驱动身份。
2. 每任务使用 seed=42 清单的全部 **50 个起点**及其原始图像。主计时测初始决策：各方法保留原生 history 长度／padding；每次恢复相同初始策略状态，动作缓存清空、CEM 残余 warm-start 清空、目标 latent 缓存未填充。保留 baseline 的 warm-start 配置值，恢复初始状态不等于将其关闭。输入视为一次有效规划请求，初始成功标记不用于跳过该计时样本。
3. 每任务／方法先用清单前 10 个起点各做一次不计入统计的完整调用作为预热；随后全部 50 个起点各测 **5 次**，共 250 次测量。运行前冻结并保存状态顺序、每次调用的 RNG seed 列表和方法执行顺序，各方法共享状态／seed 调度，但不声称其候选动作相同。每次恢复状态和 RNG 在窗口外进行；每次调用必须触发一次真实重规划。预热保留 kernel／分配器热态，不保留动作或目标缓存，也不逐次 `empty_cache`。
4. 为 PO/GF 开启所需动作梯度，模型参数固定；不以全局 `inference_mode` 包住需要反传的分支。实现统一计时模式，关闭或延后纯统计用途的候选 cost／索引转 CPU、统计量 `.item()`、分段计时同步和打印，保留算法必需计算、动作输出、数值合法性检查及轻量调用计数。仅关闭 diagnostic callback 不视为完成此要求。完整统计另行采集；保留的数值检查等实际实现成本计入主延迟。正式计时前用固定输入和 RNG 核对计时模式与正常模式的动作及候选选择一致，并归档核对结果；检查容差预先写入配置，不能为通过检查事后放宽。
5. 每任务对 250 次测量主报算术 mean(ms)，辅报 P50/P95；重复数相同，因此各起点等权。明确它们来自 50 个起点的重复测量，并保存实际独特起点数，不作为 250 个独立状态或完整部署状态分布的尾延迟。四任务平均延迟取四任务 mean 的等权平均。Selection† 复用其它三任务的计时，仅新增 Reacher 10/10 测量；不得把跨任务 pooled P95 当作逐任务 P95。
6. 峰值显存在完整规划调用边界外复位／读取，覆盖预处理与 refinement 反传；计时分支禁用内部重复峰值复位，避免抹掉此前阶段的峰值。同时报告模型加载后的基线占用，不把 planning event 内的提前读数当作完整峰值。
7. 检测到 GPU 或明显 CPU 干扰的计时批次保留并标记，条件一致后整批重测，按干扰规则采用结果，不按速度挑选。

主表 caption 明确该指标为**运行时预热后的初始完整重规划延迟**，使用初始 history/padding、无已有目标 latent cache；不将它解释为包含已有历史与缓存的所有 MPC 决策平均成本。

### 批量评测中的时间与调用数

成功率评测的环境批量为 50；随着 episode 成功结束，每次实际参与规划的 active batch 可以缩小。对每个实际规划事件记录完整策略调用的外层 wall-clock 耗时、参与 episode／slot 索引与 active batch size，并标注该运行的诊断／归档开销。不得直接使用边界不一致的旧 `encode/proposal/verify` 字段之和代替统一完整调用时间。

| 字段 | 定义与用途 |
|---|---|
| `batch_evaluation_wall_seconds` | 整批评测总耗时，包含环境与该次运行的归档开销 |
| `batch_planning_wall_seconds` | 所有真实批量规划事件完整调用耗时之和，每个事件只计一次 |
| `batch_replan_count` | 批量规划事件数；现有摘要的 `replans=len(events)` 属于此指标 |
| `episode_replan_count` | 按事件参与索引累计每个 episode 的实际规划次数 |
| `episode_steps_executed` | 每个 episode 的实际环境执行步数 |

如需要每 episode 的成本分摊，另报 `episode_amortized_planning_seconds`：对该 episode 参与的事件累计 `event_seconds / active_batch_size`。它是**批处理摊销成本**，各 episode 的分摊之和等于整批规划时间；它不是独立运行该 episode 的耗时。禁止把整批耗时完整复制给每个 episode 后求和声称总计算成本，也不能把复制在 episode 记录中的运行摘要当作该 episode 的独立计时。

正式示例视频和详细归档存在额外开销，批量总时间不直接宣称复现 LeFlow 原文 Eval Time 的精确边界；不将总时长除以 50 当成单环境延迟。单环境延迟以独立 batch=1 计时为准。

对于 Reacher 短时域，同时报告单次重规划延迟、按计划执行长度计算的名义每步成本 `mean_latency / execute_steps`、实际执行步数及每 episode 调用数。该名义成本不计提前成功、缓存状态和后续 history 变化，不作为实际累计耗时。无提前成功时，25/25 在 50 步预算内最多调用 2 次，10/10 最多 5 次；实际批处理累计成本与单环境延迟分别按上述定义报告。主表中的“快”若使用单次延迟，应明确它不是整段控制总耗时。

## 5\. 执行顺序与验收

1. **准备与冻结**：复制权重、解析归档依赖、核对哈希、冻结样本及完整矩阵，确认没有旧路径和 step=1 残留。显式冻结精度、缓存、history 和分片设置；落实裁剪测试 refine 后投影、统一计时模式及其输出一致性检查，归档验收记录。
2. **正式评测**：先完成主表四个基础版本及 Reacher 短时域主版本，再完成其余推理预算和候选裁剪测试。首批结束后核对样本身份、成功率汇总和原始记录完整性，再继续派发。
3. **独立计时**：使用空闲 GPU3；若其不可用则等待。同一卡完成全部正式计时，检测到其他计算任务干扰时保留记录并重测。
4. **资源约束**：评测使用 GPU0–3，每卡最多一个正式 worker；每条 GPU 命令显式设置 `CUDA_VISIBLE_DEVICES`，启动前检查显存并留至少 2 GiB 余量。空间低于 20 GiB 时停止派发，不删除正式数据。
5. **第一阶段验收**：924 个独立单元均有 50 个完整 episode；Selection† 的其它三任务 alias 指向对应原 Selection 单元；所有同任务同 seed 的样本一致；汇总可由归档原始结果重建；主表命名、主版本无额外候选裁剪及推理预算与冻结配置一致。核验裁剪测试的 refine 最终投影、每个计时样本的真实重规划、计时模式输出一致性及完整峰值显存；批量事件数与 episode 调用数分别可重建，若保存分摊时间则其总和必须等于批量规划时间。运行异常保留失败状态，不修改协议或静默丢弃 episode。
6. **第二阶段与完整验收**：使用已接入的官方 Sub-JEPA 四任务资产，归档原始／转换来源并完成同一批样本、统计及计时协议下的 24 个正式单元，每单元 50 episodes。两个阶段合计验收 948 单元、47,400 episodes 和完整六行主表；已有接入 smoke 不替代正式单元，第一阶段协议和结果保持可追溯。
