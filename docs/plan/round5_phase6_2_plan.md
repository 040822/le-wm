# Round 5 Phase 6.2：Reacher 总执行预算与重规划机会预实验

编写日期：2026-10-05。状态：已完成（2026-10-06）。对应第二个想法；不依赖 Phase6.1 的训练，可优先执行。

## 目标与已有证据

复用现有 Reacher R4-AB 权重，将总执行预算从 50 扩至 125 环境步，检验 25/25 能否在获得更多执行时间与规划机会后追上 10/10，并区分评分跨度、反馈频率和累计规划机会的影响。

Phase5 legacy cohort 的 P3-none 曾得到 25/25=45/50、10/10=50/50、10/25=17/50。这提示增加重规划频率本身不足以解释短时域收益；本实验保留完整推理矩阵，不只验证 P3 的有利条件。

125 的选择理由：25/25 最多执行 5 个规划块，与预算50下10/10最多5次规划调用相匹配。这里规划调用包含初次规划；若严格只数初次之后的“重规划”，两者最多均为4次。成功提前终止后实际次数更少，必须逐 episode 记录。

## 实现语义与复用检查

需要修改 `eval.eval_budget`，不能只增大环境 `max_episode_steps`。当前 `source/common/round4_eval.py` 将后者设为2×eval_budget，预算125对应250；实际控制循环仍须在125步截断。审计runner中硬编码50、统计分母、trace长度、终止逻辑、状态恢复及动作缓冲区，确保不会提前停止或额外执行。

同一方法/时域下，两个预算在前50步应具有相同随机输入和动作前缀。按episode/replan固定随机身份，避免预算或batch变化改变候选噪声；验证未成功episode的动作/状态前缀一致，已成功episode的首次成功一致。若新随机调度与历史实现不兼容，重评预算50配对参照，不强行拼接旧结果。

不同execute/score的轨迹分叉后，不声称后续状态或候选动作池相同。提前成功的episode保持原有终止方式；累计成功率将成功视为吸收事件，不为增加规划次数而强制继续运行。记录success、环境terminal/truncated和预算耗尽的独立原因。

## 预设分析

主要终点：P3-none、25/25在125步与50步预算的成功率配对差。关键参照：P3-none、25/25预算125与10/10预算50的差距。其余完整矩阵报告探索性结果，不按测试成绩重选主条件。

1. 环境步数曲线：从逐步trace计算截至每步的累计成功率，至少列出10/25/50/75/100/125步。重点比较相同环境预算下25/25与10/10。只有存在足够执行预算的单元才报告对应时点。
2. 规划调用曲线：按episode实际调用记录，统计在前k个规划块内达到成功的比例；相同最大5次机会比较25/25预算125与10/10预算50。使用完整cohort作分母，提前成功不被剔除；预算耗尽未达到后续k的单元标为截尾，不能当成观察到的失败。
3. 固定execute比较score：10/10 vs 10/25；5/5 vs 5/10 vs 5/25；1/5 vs 1/25。固定score比较execute，用于检查反馈频率与评分配合。矩阵不是完整析因设计，不将各差值称为完全独立的因果效应。
4. 记录首次成功步数、成功前实际规划次数、每episode累计规划时间、整段环境执行时间、A/B调用数、失败episode最终距离。成功episode的步数中位数须连同成功率呈现，避免忽略失败造成选择偏差。

解释边界：若25/25在125步追上10/10在50步，只能说明增加时间和规划机会可以补偿差距，不能证明原收益完全由次数造成。增加预算不改变每25步才反馈一次的频率，也不改变25步评分。若仍追不上，则说明在这个预算范围内补偿不足，支持继续调查短评分或及时反馈，但不能据此确定唯一机制。旧50步内已成功episode在125步配置中不得变成失败；违反时先检查协议或随机前缀。

成功率给Wilson区间，差值按来源episode配对聚类bootstrap；保留逐episode双向翻转，不把不同方法或候选当重复样本。单checkpoint、单推理seed、50起点仅用于探索。全部保留负结果和运行失败，不用最优条件替代完整矩阵。
