# Round5 Phase1.6：论文贡献导向的机制与效率验证

## 目标与结论边界

本阶段在24小时核心运行预算内，使用冻结的 R4-AB seed3072 epoch10 checkpoint，补齐论文需要的机制诊断、推理效率对照及短程训练干预。最终交付主推理方法、备选方法、三个研究问题的证据判断、下一轮完整训练消融假设，以及可直接纳入论文的表格和图。

本轮可确认固定模型的推理作用和固定表征上的短程训练干预；不能将短程续训解释成从头训练、多随机种子的训练耦合贡献确认。P1/P2 CEM 使用当前模型 B，是同模型推理参照，不等同于独立 LeWM/LeFlow 方法比较。

## 固定协议和数据

- Cube、PushT、Reacher、TwoRoom 四任务。闭环统一 `goal_offset=25`、`horizon=5`、`action_block=5`、episode预算50 primitive steps，每次执行25步后重规划。
- 新实验所有方法使用环境物理动作范围经现有 action normalizer 换算后的逐元素 clip。P0裁剪提案；P3裁剪后评分；PO/GF在合法范围内更新；P1/P2使用 candidate-clip，P2也裁剪 warm start。评分和实际执行动作一致。归一化合法范围不假设为[-1,1]。
- 新闭环主评测使用 FP32、Euler。保留旧 Phase1/1.5 结果为历史协议，不将其与新结果混为同表主数据。
- 历史 `legacy_50` 每任务50个起点用于机制探索和开发；冻结新确认集每任务100个起点、每原始 episode最多一个起点，排除初始成功、无效状态及已登记历史评测 episode。确认集 seed16026，按原始 episode 随机排列后抽取合格起点，保存清单和哈希；不按实验结果筛选。审计训练数据重叠；未经证实不称其为训练未见数据。
- PushT、Reacher 各最多缓存8,192个训练窗口，最多512条轨迹、每轨迹最多16个窗口；seed16026固定抽样。训练数据排除历史机制集和新确认集关联 episode。

## 实验矩阵

### 协议审计及历史结果再分析

先核查推理seed是否改变生成噪声、候选和CEM采样；区分cohort、环境和推理随机数。相同成功率不视为实现错误，也不作为随机种子有效的证据。用逐起点数据重算指导方法汇总区间，不再平均配置置信区间端点；统一复算latent MSE与物理距离；分开报告第5、25步，历史50步成功事件不得改称25步成功率。仅复用语义、动作和状态trace完全兼容的分支结果。

### 动作后果与候选排序

PushT、Reacher各使用legacy_50、S=2，每状态64个候选。预先冻结候选索引；N=1/4/16/64使用嵌套子集。每个状态另含物理零动作、归一化零动作和候选0的动作块逆序控制。合法旧分支逐元素等同于新clip动作且trace完整时可复用，否则补跑该分支。

每条动作最多执行25 primitive steps，记录第5、25步真实图像latent、物理状态、成功事件、B各prefix预测、代价、终止原因、有效长度以及预测/裁剪/执行动作hash。关闭成功自动reset；不可继续的终止保留缺失和覆盖率，不能伪造终态。

动作后果主指标为同状态预先抽取最多128个候选对上的预测latent差分与真实latent差分余弦一致性，以及预测目标代价差与真实物理代价差的符号一致率。以状态内打乱预测-动作对应作为负对照，离线置换1,000次；常量或近零差分标为不可识别并报告覆盖率。

决策指标包括随机候选、B选择、真实未来latent选择、物理oracle的成功率，B−random配对差、物理regret和N曲线。真实latent和物理oracle明确作为诊断上界。第5/25步只在完全相同的有效候选子集比较四种选择器，并报告每状态覆盖数；全池25步内成功事件另行汇报。

### PO/GF方向效应

PushT、Reacher各50状态，S=2，候选0/1及其noise固定配对。执行原提案、PO（2次B反向，η=.01，RMS半径=.2）、GF（两步各1次B反向，η=.01，沿用flow-state局部半径=.2），以及各自实际最终RMS位移匹配的随机方向对照。PO/GF只称B反向次数匹配，不称总计算量或更新空间相同；GF额外A调用、最终动作位移均报告。所有修正动作最终评分和执行均使用合法clip动作。

随机扰动用固定seed生成，裁剪后以一维缩放匹配实际RMS位移，最多尝试32方向；无法匹配则记为无效配对并报告覆盖率。主要报告25步物理改善、匹配随机方向优势、预测/真实latent/物理改善、预测改善但物理恶化比例，以及GF−PO状态配对差和实测计算量。第5步仅作辅助。新增修正分支上限800条，不做K/η/R网格扫描。

### 新起点闭环和效率

四任务各100起点，推理seed42/43，9种预设方法，合计7,200 episodes：

| 方法 | 固定配置 |
|---|---|
| P0 | S=2，N=1 |
| Random-64 | S=2，产生64条候选后均匀随机选取一条，不调用B |
| P3 | S=2，N=64 |
| P0+PO | S=2，K=2 |
| P0+GF | S=2，每个flow step一次B反向 |
| P3+PO | S=2，N=64，每候选K=5 |
| P1 CEM | 300候选，30轮，elite=30 |
| P2 CEM | S=1 warm start，300候选，30轮，elite=30 |
| P2-small | S=1 warm start，64候选，5轮，elite=7 |

CEM方差scale=1；PO/GF步长=.01，RMS半径=.2。Random-64与P3在相同观测使用同一候选生成随机流，后续环境轨迹分叉后各自正常采样，不声称整段闭环候选相同。主对比为P3−Random-64、PO−P0、GF−PO以及P3/P3+PO对预定CEM参照。锁定确认集不再用于调参；若不能支持既定主/备选，报告未确认及完整Pareto结果。

### 冻结表征下的短程训练干预

PushT、Reacher各训练三臂，共6个run；已有checkpoint为Frozen参照。

| 训练臂 | B动作输入 | 对预测动作的梯度 |
|---|---|---|
| Continue | 50%记录动作、50%预测动作 | 保留 |
| Detach | 同Continue | detach |
| Recorded | 全部记录动作 | 不适用 |

三臂冻结encoder/projector和BN统计，缓存相同latent，仅更新原A/B参数；D/E专用参数冻结。所有run从相同初始权重重新初始化AdamW，seed3072，batch128，lr=1e-5，weight decay=1e-3，gradient clip=1，固定1,000 optimizer updates，保存0/500/1,000步，仅用1,000步正式比较。共享训练窗口顺序、flow noise、τ、混合mask。Recorded也保留相同的辅助mask、B timestep和loss weighting，只替换B实际输入动作，以隔离动作来源。

B loss权重1，保留A flow loss。冻结表征使SIGReg对表征没有梯度，不重复图像编码，仅记录常数诊断。训练后在同一固定动作池批量评分，无需重跑环境；在新确认集对每臂运行P0/P3、两个推理seed，共2,400 episodes，并检查P0退化。

Continued−Frozen包含额外训练效应；Detach−Continue隔离预测动作梯度干预；Recorded−Detach检验匹配条件下预测动作输入影响。结果只支持固定表征、固定预训练起点的短程机制判断，并产生从头匹配训练假设。

新增独立 `scripts/round5_phase1_6.py`、`config/round5/phase1_6.json`，报告输出 `docs/report/round5/round5_phase1_6_report.md`，数据写入独立Phase1.6输出目录。提供 `audit / prepare / calibrate / run / analyze / export-paper` 子命令。worker常驻加载模型、数据、环境；候选真实结果和模型评分分开，支持原子分片写入、锁和断点续跑；结果带checkpoint/cohort/config/code hash。

用户授权补充（2026-09-29）：推理任务可使用GPU0–7，训练仅使用GPU0–3；派发前按当前可用显存和预算余量选择设备，每条GPU命令都显式设置 `CUDA_VISIBLE_DEVICES`。此轮GPU4–7仍按配置的低显存评测护栏执行（实测任务峰值不超过8 GiB），并遵守工作日白天尽量不用的仓库规则。每张卡最多一个本轮worker；评测worker从8个环境起步，训练缓存DataLoader workers=0；限制评测线程以免CPU超额并发。计时优先GPU3串行隔离。

资源护栏：评测任务显存余量至少实测峰值+2GiB，GPU4–7单任务峰值不超过8GiB；训练余量峰值+6GiB；主机可用内存至少64GiB且大于下一worker实测峰值1.5倍；一分钟load/CPU数超过.75时暂停派发；持续swap I/O或内存压力时降低并发。GPU4–7已由用户授权用于低显存评测，白天只在GPU0–3无法按预算完成时使用。

24小时从首次运行校准起计，含缓存和运行时间。0–2小时审计、校准、冻结确认集；2–16小时训练、机制和闭环并行；16–20小时终点评测和补缺；20–24小时隔离计时、分析与论文导出。校准后按实测耗时排序配对任务。第22小时停止派发预计不能按时完成的新分片；第24小时保存进度并输出报告。失败任务最多自动重试2次，基础设施失败不算控制失败。时间不足按冻结的起点次序停止，不按成功率删结果；用共同完成样本分析并披露分母。上限：9,600闭环episodes、6,700候选/控制分支、800修正分支、6个训练run。

正式方法逐任务、batch1及batch50测时：每种方法10 warmup、50次同步计时，使用5批固定真实观测，计时覆盖完整推理并记录A/B前向、B反向、峰值显存、吞吐。记录计时窗口GPU进程、利用率、CPU负载；受干扰窗口最多重测2次，否则标记受干扰，不用于加速主张。吞吐用总观测数除以总耗时，另报告逐任务值；不能平均逐任务吞吐冒充混合吞吐。

## 统计、论文产物与验收

起点为抽样单位。先在起点内平均推理seed/候选，再做10,000次配对state-cluster bootstrap。四任务宏平均等权汇总任务结果。不把候选数、训练步数或推理seed当独立样本。主要检验预先固定为P3−Random-64、PO−P0、GF−PO、Detach−Continue、Recorded−Detach；推理和训练分别组成检验族并使用Holm校正，其余标注探索性。成功事件、固定物理时点和覆盖率分开报告。

生成4张LaTeX/CSV/JSON论文表：①9种方法闭环成功率及逐任务延迟；②预测动作后果一致性、随机/B/真实latent/物理oracle和regret；③PO/GF相对匹配随机方向的真实收益及成本；④Frozen/Continue/Detach/Recorded训练干预的固定池和P0/P3结果。另生成成功率-实测延迟前沿图和PushT/Reacher候选数曲线图。更新论文实验段、摘要阶段性结果、贡献表述、讨论和证据快照；每个表格单元可追溯至配置、checkpoint、cohort及结果hash。

预设判定：

- 只有动作差分超过打乱对应负对照、且与真实物理变化一致，才写“B具有可验证的动作后果辨别能力”。
- 以新确认集P3−Random-64为排序主要证据；局部任务结论限定到任务。
- 梯度只有真实收益超过匹配随机方向并反映到闭环结果，才作为决策贡献。预测cost下降不足以证明有用。
- 只有相对P2大预算CEM，成功率差单侧95%下界大于−2pp、每任务下界大于−4pp且延迟至少降低20%，才写“在预设性能容差内降低成本”。不满足时写未确认非劣性，不能把区间跨零当作等价。
- GF只有经校正的真实收益，或满足性能容差且比PO延迟低至少20%，才进入主方法；否则作为消融报告。
- 训练结果仅称冻结表征短程干预。根据结果明确下一轮需要检验的连接、方向、任务和决策指标。

实施验收还包括：同状态/RNG重放一致；clip与实际动作一致；跨分片seed可复现且不同seed有效；P3与Random-64候选匹配；PO/GF梯度调用正确、随机扰动RMS匹配；固定时点和终止处理正确；encoder/BN冻结、detach路径有效；Recorded与Detach随机辅助条件一致；缓存与在线冻结编码结果在容差内；分片无重复或静默缺失；论文表格数值与分析JSON一致。

## 执行记录补充（2026-09-29）

首轮分任务并行计时遇到共享主机CPU争用：多worker同时运行时主机负载升至1.49/CPU，计时器只检测GPU进程，不能识别CPU调度对完整 `policy.get_action` 墙钟延迟的影响。因此该轮已完成行只保留在 `outputs/round5/phase1_6_timing_host_contention_diagnostic/` 和 `outputs/round5/phase1_6_seed3072/timing_host_contention_diagnostic/` 作诊断，全部排除出论文速度结论。正式计时最初改为GPU3单worker；串行速度表明需要明显延长交付周期。为缩短计时，在 BLAS/OpenMP 与 PyTorch 线程固定为1、并确认主机负载低后，正式测量调整为GPU0–3每卡一个任务分片，每个GPU至多一个本轮worker。每个五组观测窗口记录指定GPU进程和主机负载边界；主机负载超过0.75/CPU或指定GPU出现其他计算进程的窗口最多重测两次，最终仍受干扰的条件不计入速度主张。各任务独立写分片汇总，合并时验证配置/代码哈希、36条条件完整性与唯一性。GPU4已用于首轮TwoRoom推理诊断（校准峰值0.723 GiB）；正式重测只使用GPU0–3。
