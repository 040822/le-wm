# 下一轮计划：定位耦合收益，检验并改善 B 的动作选优能力

## 一、目标与实验边界

本轮围绕四个问题建立证据链：

训练耦合是否改善 A、B？ 区分参数共享、预测动作混合、跨分支梯度。

B 是否能从已有候选中挑出更好的动作？ 区分候选覆盖不足、动力学预测误差、latent 距离不适合任务目标。

PO/GD 是否带来真实收益？ 比较局部物理改善、闭环成功率与额外计算成本。

怎样改善 B？ 优先修改监督，再检验 B 专用小模块；最终必须改善决策表现。

已确定的边界：

首轮任务：Push-T、Reacher。 筛选后的结果扩展至 Cube、TwoRoom；Phase3 三任务先通过评测有效性检查。

主方法仅使用离线图像和动作。 物理状态用于诊断；新增交互训练、物理标签训练分别标注为额外数据对照、特权监督对照。

首轮训练种子 3072；通过筛选的关键比较扩展为 3072/3073/3074。

GD 统一指 guided_flow；PO 指 post_opt。

不继续全面扫描推理超参数，不新增 DP 基线。

“LeWM、LeFlow 也存在选优缺口”作为待验证假设。LeFlow 使用冻结 world model 对解码动作进行 rollout 评分，因此值得检验，但论文的方法描述本身不构成其存在缺口的证据。LeFlow 原文

## 二、阶段 A：建立可信评测，定位选优缺口

### A1. 数据与协议

复用 Phase1.5 的分支执行、状态恢复、动作池及物理 trace 工具，新增独立实验目录，不覆盖历史结果。

历史 legacy_50 和 round3 已反复使用的 final cohort 均作为开发材料。

新建每任务 100 个开发起点、200 个锁定测试起点：初始未成功、每原始 episode 至多一个起点、按起始物理距离分五层。

开发、测试、后续交互采集按原始 episode 隔离；新测试排除已用于历史调参评测的 episode。

新测试称为“未参与本轮选择的评测集”。检查历史 checkpoint 的训练数据覆盖，不能未经核验宣称“未见训练轨迹”。

保持 goal offset=25、闭环预算=50、horizon=5、action block=5、每次执行5个 primitive steps 后重规划；成功阈值沿用当前任务定义，不同时改变采样和成功判据。

先完成零控制、合法随机控制、数据动作重放检查。零控制区分物理零与归一化零；数据重放核对状态恢复、动作索引和目标行。发现不一致时先修复并重新冻结协议。

Phase3 仅先做同样的检查及初始成功统计，暂不扩展完整训练矩阵。

评测分两部分：

固定动作池评价 B：动作池不随训练臂变化。
原生闭环评价系统：A-only/P0、P3、B+CEM。

核心差值为：

联合 P0 − 独立 A-only：B 训练是否帮助 A；
联合 B − B-only：A 训练是否帮助 B；
P3 − P0：推理选优是否有收益；
shared DiT − independent DiT：共享主干的作用；
mixed-detach − recorded-action：动作混合的作用；
mixed-gradient − mixed-detach：跨分支梯度的作用。

不以梯度余弦相似度等内部量单独判定正迁移。

### B2. PO/GD 实验

先在当前 checkpoint 上完成；选出的 B 改进版本再复测同一组设置。

比较：无引导、PO、GD。
flow steps=1/2，候选数=1/16。
S=1 时 PO/GD 均使用1次 B 梯度计算；S=2 时均使用2次，GD 分配到两个生成步骤。
小网格仅保留步长 {0.01, 0.03} × 总 RMS 上限 {0.1, 0.2}。
两任务开发集共同选择一套配置；先按平均成功率，差距不足2个百分点时选实测延迟更低者。
每次修正配同起点、同初始噪声、同实际 RMS 的随机扰动对照。

分别报告：

预测代价降低是否对应真实 latent／物理距离改善；
相对随机扰动的增益；
模型代价下降但物理结果变差的比例；
闭环成功率；
batch1 的 p50/p95 延迟、实际 A/B 前向与 B 反向次数。

GD 会改变后续生成路径，因此只在初始噪声和预算上配对，不能假定它与 PO 具有相同的最终未修正动作。

解释原则： 全局选优差与局部梯度有用可以同时存在；PO/GD 有效也不自动证明训练耦合有效。

## 四、阶段 C：针对 B 的缺口进行有限修改

### C1. 优先修改监督，保持架构

z_H 来自执行该记录动作后的真实离线图像。

每个 transition 配4个目标：真实终点、同轨迹另一个未来帧、两个其他轨迹帧。

校准权重固定为1；不进行大规模 loss 权重搜索。

原 A loss 保留，用于约束共享主干更新导致的动作生成退化。

训练5000个 optimizer updates，batch128、学习率 1e-5，在0/1000/2500/5000记录开发指标，正式比较固定5000终点。

这个损失检验的是：让 B 更准确地保留与目标距离有关的预测信息，是否能改善决策。 它不提供未执行动作的真实结果，不能被解释为已经解决反事实覆盖不足。

若 Continue 相对 Frozen 退化，Goal-cost 必须同时超过二者才算有效。

### C2. 必要时加入 B 专用残差适配器

当 C1 未通过筛选，或改善 B 的同时明显损害 P0 时，启动此分支。

冻结原 encoder、共享 DiT 和 A。

在 B 的每个未来预测 token 上增加 LayerNorm → Linear(128) → GELU → Linear(latent_dim) 残差模块。

最后一层零初始化，初始输出严格恢复原 B。

输入仅为 B hidden feature，保持动力学预测不依赖目标图像。

比较“adapter＋latent MSE”和“adapter＋latent MSE＋cost calibration”；训练预算与 C1 相同。

这样可检验：原失败是否部分来自修改共享参数时破坏 A，以及 B 专用容量是否有帮助。

### C3. 额外交互仅作为独立对照

在与开发／测试隔离的128个训练起点，每起点执行8条候选，最多25步，共不超过25,600环境步／任务：

4条 A 候选；
2条 LeFlow 候选；
2条 A 候选的局部扰动。

所有模型使用同一份实际动作—未来图像分支数据。比较：

同样增加训练步数，但只使用原离线数据；
加入真实分支 latent MSE；
在2基础上加入同起点、同目标、同时间长度的候选成对排序损失。

普通排序监督使用实际未来图像的 latent 代价；使用物理距离标签的版本单独作为特权监督上界。记录有效排序对数、代价尺度、梯度范数及 A 的变化，重点复核 round3 ranking 实验是否存在监督不足或共享更新副作用。

若阶段 A 表明真实图像 latent 的评分本身很差，则不能期待动力学校准消除该缺口。此时用物理监督上界确认改善空间，本轮结论明确限定为“评分几何仍需改进”，不继续盲目叠加动力学损失。

## 五、筛选标准、实现验收与论文产物

### 筛选与扩展

首轮单种子结果仅用于筛选：

固定池选优成功率提升至少 5个百分点，或物理 regret 降低至少 10%；
同时闭环成功率相对对应基线下降不超过 2个百分点；
零 oracle regret 等不适用情况不计算相对降低比例。

通过者最多保留两个。排序增益只决定是否值得进一步验证，不等于论文成功条件。

随后：

对保留方案及其直接对照补齐三个训练种子；

冻结推理配置，在锁定200起点测试；

按起点配对 bootstrap，报告逐训练种子结果，不能把所有候选当作独立样本；

扩展 Cube、TwoRoom；Phase3 通过评测检查后仅测试冻结方案；

正式收益要求体现为闭环成功率提升，或在预先固定的性能容差内显著降低规划成本。未检出差异不直接称为等价。

### 接口与验收

新增统一的候选评分接口，支持本方法、LeWM、LeFlow 后端；动作以物理单位保存，各后端自行归一化。结果必须包含 checkpoint／cohort／动作 hash、候选来源、评分器、执行长度、终止原因和真实结果。

训练配置增加独立分支、latent 权重模式、cost calibration、B adapter 开关；默认关闭新功能，保持旧 checkpoint 的加载和推理行为。

必要验收包括：

同一状态与 RNG 恢复后，固定动作重放结果一致；
评分动作与实际执行动作一致；
固定候选顺序变化不改变逐候选评分；
分离 DiT 无意外参数共享，detach 确实阻断对应梯度；
adapter 零初始化恢复原输出，训练后冻结 A 输出不变；
PO/GD 确有 action gradient，反向次数符合配置；
排序对确实共享起点、目标和有效时间长度；
开发、测试、交互数据隔离检查通过。

GPU 仅使用0–3，启动前检查显存，每条 GPU 命令显式设置可见设备。先完成诊断与小规模运行验收，再展开训练矩阵。

### 最终交付

形成四组论文证据：

共同缺口： 不同候选来源、不同评分器的选优能力及误差分解。
耦合归因： A 的改善、B 的改善、共享与跨分支梯度的独立作用。
推理作用： PO/GD 的真实收益与成功率—延迟关系。
方法改进： B 修改前后的固定池与闭环结果，区分离线、额外交互和特权监督。

执行顺序固定为：协议检查 → 跨模型诊断 → 耦合及 PO/GD → 监督修改 → 必要的 adapter／交互对照 → 多种子独立测试。 每阶段允许得出无收益结论；后续投入由这些结果决定，不以必须证明当前设计有效为前提。
