  ## 1. 目标与固定口径

  本轮不再训练主模型，而是回答三个问题：

  1. B 是否理解动作后果？ 不同动作的预测差异，是否对应真实环境中的后果差异？
  2. B 是否能帮助决策？ 候选排序与梯度修正，分别能带来多少真实收益？
  3. 能否替代大规模 CEM？ P3、PO、GF 能否在成功率与实际延迟之间取得更好的折中？

  最终交付不是一个“最高成功率配置”，而是：一个主推理方法、一个备选方法，以及下一轮训练消融需要验证的明确假设。

  ## 3. 工作流 B/C：真实后果诊断与物理 probe

  ### 3.1 固定候选池：把“提案不好”与“B 选错”分开

  在每个任务的 50 个初始状态上建立候选池：

  - 六个 S 值，每个生成 256 条 A 候选。
  - 不同 S 共用对应的初始 flow noise，便于配对分析。
  - 每条动作序列在真实环境中执行一次，保存第 5、10、15、20、25 个 primitive step 的真实状态及编码。
  - 所有 N 的离线排序分析使用同一候选池的前 N 条。

  增加以下控制动作：

  - 数据轨迹动作、S=1/S=2 的首条 A 候选，作为三个锚点。
  - 每个锚点：8 个固定随机方向，3 个 RMS 扰动尺度 .03/.1/.3，正负两向，共 144 条。
  - 每个锚点增加动作块倒序、循环移位一块、固定随机重排，共 9 条。
  - 64 条标准高斯归一化动作。
  - 物理零动作、归一化零动作各一条；分别记录，不称为通用 no-op。

  包含原始锚点，最多约 35.1 万条真实分支，重复动作可以去重缓存。

  这里的固定池用于诊断。不能用初始候选池的结果替代不同 N 的完整闭环评测。

  ### 3.2 梯度修正：预测改善是否兑现？

  每个状态固定使用：

  - PO：S=1、2、5、16，各取前两条候选。
  - GF：S=2、5，各取前两条候选。
  - PO 扫描 A2 的 K、η、R；GF 扫描 K、η，固定 R=.2、L=min(3,S)。

  每条修正动作配一个相同 RMS 位移的随机方向修正，从相同环境状态执行，作为梯度方向对照。总计约 10.1 万条额外分支；相同 PO 更新路径共享中间结果。

  记录：

  - 预测 cost 改善量、真实 latent cost 改善量、真实物理距离改善量。
  - 真改善比例、真退化比例。
  - model exploitation 比例：预测改善但真实结果恶化。
  - 动作位移、动作饱和比例，以及效果随优化强度的变化。

  GF 的预测改善量在最终完整动作上重新用 B 评分，不把中间 flow 状态的不同目标值直接相减。

  ### 3.3 物理 probe：编码器看得见，B 才有可能预测对

  数据来自原离线数据集，排除包含评测起点或目标的全部轨迹。按轨迹划分，不按随机帧划分：

  - 固定 seed2026，最多选择 1,000 条轨迹，80%/20% train/validation。
  - 每轨迹最多均匀抽取 100 帧；数据不足时全部使用并报告实际规模。
  - 训练标签仅使用当前帧可观测位置/姿态；不把单帧速度作为主指标。

  探针设置：

  - 主结果：标准化目标上的线性 Ridge，验证集选择 α∈{1e-4,1e-3,…,1e2}。
  - 补充：单隐藏层 128 维 ReLU MLP，Adam、lr=1e-3、batch256、最多50epoch、patience5，seed0/1/2。
  - 基线：训练集均值、打乱训练标签的 Ridge、同架构随机初始化冻结编码器上的 Ridge。
  - Probe 只在真实图像编码上训练，再应用于 B 预测的 future latent；不使用反事实评测分支训练 probe。

  主要物理量：Cube 方块位置；PushT 推杆/物体位置与角度；Reacher 关节位置；TwoRoom agent 位置。周期姿态用 sin/cos 表示，报告时还原角度误差。

  报告两种误差：

  1. 从真实未来图像编码解码物理量的误差。
  2. 从 B 预测 future latent 解码物理量的误差。

  第一项是表示与读出器的参照误差；第二项额外包含动力学预测误差。不能仅凭第二项差就断言 B 没有学到物理。

  ### 3.4 分支实验的必要安全检查

  - 同一完整 simulator state 恢复后，同一动作重复执行应得到一致结果；同时恢复环境随机状态。
  - 保存模型提出的动作、反归一化动作和环境实际执行动作。
  - 诊断分支关闭成功后的自动 reset，记录成功事件；遇到真正的不可继续终止，标记有效长度，不伪造未来状态。
  - B 对原始提案的预测为主分析；对实际裁剪动作重新预测为补充，以识别动作执行不一致造成的误差。
  - 常量候选池的相关系数记为未定义，不能记成零。

  ## 4. 工作流 D：公平计时与并行执行

  ### 4.1 “Fast”单独测，不使用混跑耗时证明

  计时必须包含实际推理路径：编码、A 提案、B 评分/梯度、CEM 更新及动作输出；环境运行时间另外报告。

  分两层：

  - 全部配置做粗测：5 次 warm-up、10 次同步计时，使用固定真实输入。
  - 固定锚点及粗测 Pareto 前沿配置做精测：20 次 warm-up、100 次同步计时。

  分别报告：

  - 单环境决策延迟 p50/p95。
  - batch50 吞吐量。
  - 峰值显存、A/B 前向和 B 反向调用数。
  - success–latency Pareto，以及相对 P1/P2 的成功率差和速度比。

  精测使用无其他 GPU 工作负载干扰的时段；无法隔离的结果标记为受干扰，不用于主要加速主张。批处理或精度优化若改变采样/数值语义，单列为新配置，不直接继承旧成功率。

  ### 4.2 四条队列并行，但先通过小规模校验

  执行顺序：

  1. 入口校验：历史索引、权重/cohort hash、GF/PO 等价性、状态恢复、动作归一化。
  2. 小规模校准：每任务取固定前5个样本，测试 P0、P3、PO、GF、低/高预算 CEM，以及真实分支；测显存、耗时、CPU/渲染压力。
  3. 并行铺开：闭环扫描、候选池、probe 特征抽取/读出器分别排队；Reacher、PushT 优先，Cube、TwoRoom 随后补全。
  4. 收尾：补采样 seeds、隔离精测、统一分析。

  默认使用 GPU0–3，每次启动显式设置 CUDA_VISIBLE_DEVICES，确认可用显存并预留余量。GPU4–7 只在获得明确授权后承担低显存评测；白天优先避免使用，读出器训练保持在 GPU0–
  3。

  ## 5. 实现接口、验收与研究决策

  ### 实现交付

  新增独立入口，不修改 Phase1 冻结结果：
  - docs/report/round5/round5_phase1_5_report.md：完整结果、复用记录和方法收敛建议。

  产物统一写入独立的 Phase1.5 输出目录。任务 ID 包含 checkpoint/cohort、推理参数、推理 seed 和执行语义；支持锁、原子写入、断点续跑。基础设施失败不计作任务失败率或
  控制失败，修复后原条件重跑。

  ### 验收

  - 网格去重后数量符合计划，历史复用均可追溯。
  - 闭环结果每条件恰好覆盖原50个样本，失败不能静默丢弃。
  - probe 训练/验证轨迹与评测关联轨迹无交叉。
  - 同状态恢复、动作往返归一化、GF step1 等价性均有测试。
  - 相关性、regret、修正收益先按状态计算，再汇总；置信区间按状态聚类 bootstrap，10,000 次，不能把数十万候选当成独立样本。
  - 大规模搜索结果明确标为探索性；重复使用这50个样本不能得到无偏的最终泛化结论。

  ### 最终必须给出的四个判断

  1. P3 值不值得保留？ 看同候选池中 B 是否稳定优于随机选择，以及 oracle–selected 差距。
  2. PO/GF 是否能替代 CEM？ 看真实修正收益与成功率—延迟前沿，而不是只看预测 loss 降低。
  3. GF 是否值得单独讲？ 若不比 PO 提供稳定的真实收益或效率优势，就从主方法中移除。
  4. 下一轮该怎样研究 R4-AB？ 根据失败模式安排参数共享、预测动作输入、B→A 梯度三类匹配训练消融；本轮结果只产生假设，不替代这些实验。
