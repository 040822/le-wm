# CVPR Table 1 正式实验计划复查

日期：2026-10-03（北京时间）。复查对象：[cvpr_table1_plan.md](../../plan/cvpr_table1_plan.md)。

**后续范围修订：**用户已明确 baseline 保持 25/25、CoWM 主结果无额外候选裁剪，仅添加 Reacher 短时域 Selection；同 A+LeWM、Random-64 等 Table 2 内容本轮不做。下文为首轮复查的历史建议，其中扩大主表对照、调整 baseline 时域、正式 clip 等建议已由 [范围与计时修订](cvpr_table1_timing_and_scope_20261003.md) 取代，以更新后的计划为准。

## 结论

计划的资产归档、公共样本、统一重评、成功率与计时分开、保留失败记录和禁止按正式成绩更换方法等安排是合理的。现有计数也正确：4 个无引导配置 + 7 个配置 × 2 档预算 = 18；两种动作处理得到 36；加两个 baseline，得到 912 单元、45,600 episodes。

**但不建议按当前版本直接冻结为论文正式主实验。** 需要补上评分器与随机选择对照，处理动作裁剪的实现缺口，并在 Round5 方法选择结束后明确时域与权重冻结规则。更大的 GF/PO 网格不能替代这些对照。

单训练 seed、复用固定 checkpoint、六评测 seed 的安排可以作为正式的固定模型 benchmark。它能报告这些部署系统的表现；不能仅凭该主表证明训练耦合的普遍收益、训练稳定性或严格未见数据泛化。此复查不把新增多 seed 训练或 Phase1.8 全矩阵作为默认要求。

### Phase1.7 已收尾，不能继续沿用报告开头的“仍在运行”判断

2026-10-02 末尾追加的收尾记录已经覆盖报告开头的旧状态：Recorded-control/B-only 八个 retry3 训练及已安排评测完成；Recorded-clean 没有启动，本轮按用户要求暂停。

最终两个任务、两个训练 seed 的证据没有建立 Joint-B 相对独立 LeWM 或 B-only 的稳定排序优势。PushT/4096 的 P3 结果在该任务×seed 的两项检验族中有局部信号，扩展到八项比较的敏感性 Holm 校正后 p=0.180；Reacher 的方向随 seed 改变。不能把早期 epoch-2 的较大排序差写成最终模型的一般性质。

在线 `rank_1.0` 在 PushT 上相对独立 LeWM 有 +8.5 pp 的锁定比较结果（两任务 Holm p≈0.012），但相对原 Joint-B 的 +4.5 pp 区间包含零；Reacher 的主要比较也不确定。它还使用新增真实环境分支监督，属于另一种数据设定，当前不适合升为离线主表的默认方法。

来源：[Phase1.7 报告末尾](../round5/round5_phase1_7_report.md)，以及 `outputs/round5/phase1_7/epoch10_retry3_primary_family_analysis.json`。

**报告文字的一处纠正：**末尾把上述 P3 终点称为“25 步成功率”，实际主分析读的是 `episodes.jsonl` 的最终 `success`，原始 `eval_budget=50`。Joint 的最终成功数为 PushT 181/180、Reacher 42/52；对应 25 步内首次成功数分别是 177/175、23/28。这里应按 **50 步预算内成功率**解释，不能与固定候选池的 25 步分支成功混用。

### 已完成的 Phase5：评分／执行时域是最值得吸收的新内容

以下保持原 5×5 模型、S=2、N=64，只改变 execute/score；每格 50 起点，均为探索性结果：

| P3 无引导 | execute/score=25/25 | 10/10 | 5/5 |
|---|---:|---:|---:|
| Reacher | 90% | 100% | 100% |
| Cube | 100% | 82% | 76% |
| PushT | 98% | 60% | 58% |
| TwoRoom | 100% | 98% | 90% |

这支持把 Reacher 的短前缀作为正式候选，不支持四任务统一缩短到 5/5。Reacher 的 5/25 只有 30%，进一步说明只缩短执行而保持长评分，并不能获得同样收益。

这些 P3 原始结果的 `action_bound_mode=none`，而当前正式计划是 `clip`。因此它们用于提出候选配置，**不能直接替代正式 clip 结果**；冻结前需要裁剪协议桥接。报告元数据中的 `initial_success_filtering=True` 实际来自 `selected_initial_success_not_filtered=True`；结合原始诊断应解释为未过滤，不能按表头理解为已经过滤初始成功。

同一 Reacher legacy cohort 的 baseline 前缀实验也显示：

| 方法 | 25/25 | 10/10 | 5/5 |
|---|---:|---:|---:|
| LeWM | 72% | 88% | 90% |
| LeFlow | 86% | 98% | 94% |

四个短前缀比较统一 Holm 后均未到 0.05；当前 LeWM 是历史本地模型，与正式计划拟使用的发布 backbone 不同。该结果足以要求为 baseline 提供同样的时域机会，但不足以宣布跨方法的稳定收益。

来源：[Phase5 多任务报告](../round5/round5_phase5_pre_report2.md)、其 `analysis/analysis.json` 与对应 `result.json`；[baseline 前缀报告](../round5/round5_phase5_baseline_horizons_report.md)。

## 2. 正式启动前需要处理的问题

### A. 方法与时域冻结缺少和正在进行的预实验之间的接口

计划第 23、74、107–108 行直接锁定 5×5、全段 25 步执行、Round4 权重；原生结构实验却以确定最后主方法为目标。需要先明确选择：本轮 Table 1 固定报告旧模型，还是承接该预实验的最终模型。

建议保留准备资产与整理协议的工作，把正式成功率运行放在最终方法冻结之后。新增显式字段：`model_action_blocks`、`action_block_env_steps`、`execute_steps_env`、`score_steps_env`、`goal_offset_steps`。这能避免将 H=5 误读为执行 5 个环境步。

若保持旧模型，最小扩展是为 Reacher 在开发数据上比较 25/25、10/10、5/5，再锁定一个时域候选；其他任务的旧证据偏向保留 25/25。时域允许按任务设置时，应明确这是预先声明的任务配置，并给 LeWM/LeFlow 相同开发选择机会，同时保留统一 25/25 的参考。不能只把 CoWM 切到最有利的短时域，再与固定 25/25 baseline 比较。

若采用新原生结构，需要先有闭环结果、动作与预测时点对齐及协议桥接。当前仅两任务训练，不能将混合旧／新结构的四任务结果默认为统一新模型；应明确任务范围或方法配置，也不能因为探索结果不佳删掉已声明任务。

### B. 缺少两个能够解释主表成绩的重要对照

当前 38 配置没有 **同 CoWM-A + LeWM 的 P3** 和 **Random-64**。它们比继续扩大 GF/PO 更新次数更有解释力：

- P3 vs Random-64：在相同候选分布下，B 选择是否有用。
- CoWM-A+B vs 同 A+LeWM：保持动作生成来源，比较完整评分系统的质量与成本。
- P0-PO vs P0：修正是否值得其额外计算。P0 已在完整矩阵，应在主表或紧邻的消融表中可直接看到。

Phase1.7 最终结果不支持普遍的 B 排序优势，因而同 A+LeWM 尤其重要。该对照应使用 LeWM 自身 encoder、normalizer 和 history，并将相同物理动作转换到其接口；它比较完整评分系统，不是共享参数的单因素训练消融。闭环分叉后只能匹配候选随机流，不能声称全程处在完全相同候选池。

若只为两个对照增加一个冻结版本，不再复制全部引导网格，则增加 2×4×6=48 单元、2,400 episodes；原总量变为 960 单元、48,000 episodes。这是最低限度的增量，尚不含时域、baseline 裁剪或预算扩展。

### C. “正式 clip”存在具体实现缺口

计划第 57 行要求评分与执行动作一致，但当前代码存在两种不同情况：

1. `source/policy/round4.py:710` 的 `post_opt_refine` 先选择已裁剪候选，再调用优化；第 746 行起直接把更新结果装入执行缓存，中间没有再次 `_project_candidates`。因此 **P3-PO-refine 在 clip 模式仍可能产生越界动作**。它的投影统计还来自优化前的候选，不能证明最终动作合法。
2. `source/model/fast_lewam/jepa.py:656` 的 guidance cost 直接把 `clean_actions` 送入 B；PO/GF 内部只约束 RMS 位移，不接收物理边界。现有 P0/P3 的最终投影发生在生成／优化之后。因而“最后的候选评分一致”与“每次梯度 cost 都针对可执行动作”并不是同一个保证。

正式协议至少应保证 refine 后再次合法投影，归档最终选中动作、投影前后代价和实际位移。对于内层 GF/PO，必须明确采用“无约束代价优化后投影”还是“以合法投影动作的代价优化”；若采用后一种，需要调整实现并在开发数据上桥接，不能把改变后的数值冒充旧算法复用结果。

另外，当前 planning event 在 refine 前读取 `max_memory_allocated`（`round4.py:701`），可能漏记 refine 的显存峰值。正式计时应在完整调用外层复位、同步并读取峰值。

### D. 只有 CoWM 做裁剪对照，无法完全排除动作处理带来的差异

计划第 57 行给 CoWM 使用 candidate clipping，第 64 行却明确不给 LeWM 增加候选裁剪。保留 baseline 原生实现可以用于比较部署系统；但成绩差不能因此单独归因于模型或耦合。只测 CoWM 的 clip/none，仍不知道 baseline 能否从同样的合法候选处理受益。

建议保留原生 LeWM/LeFlow 作为明确标注的 reference，并补主 operating point 下的统一物理动作处理对照。对 CEM，投影应在 cost 与 elite 更新使用候选之前；对 LeFlow，在解码成物理动作后、rollout reranking 之前处理。各模型使用自己的 normalizer，不强制其归一化数值边界相同。

### E. mean±std 合理，但不足以支持论文比较性主张

计划第 112–114 行准确说明 std 来自评测 seed。不过 std 是描述性波动，不是方法差值的置信区间；六个 seed 也不能代表训练随机性。

建议保留主表 mean±sample std，并补预先指定主要对比的配对差值及区间：P3−Random-64、P3−同 A+LeWM、PO2−P0，以及论文需要强调的系统参考比较。样本清单允许同 episode 多起点和跨 seed 重复，重采样应保留同一来源 episode 的依赖及重复记录，而不是把每任务 300 行一概视为独立。检验族和校正规则须在看正式成绩前记录。

保留上游初始成功样本符合当前 benchmark 约定。额外报告初始成功比例、独特 episode／起点数量，并利用现有逐 episode 记录给出初始未成功子集的描述性结果即可；它不应按成绩取代正式主表，也不需要因此另开完整训练矩阵。

### F. 计时还需冻结缓存、历史和真实重规划语义

同 GPU、batch=1、CUDA 同步、完整 policy call 的安排正确，但不能直接在相同状态上连续调用 `get_action` 后取平均。策略会从缓存输出后续动作；`stable_worldmodel/policy.py:379` 只在缓存为空时调用 solver。

每次正式测量必须触发且记录一次真正的 planning event，并固定相同 history、goal cache 和 CEM warm-start 状态。预热只用于运行时预热，不能使某方法的目标编码永久跳过却让其他方法反复编码。现有 Phase1.6 计时已有 `_needs_flush` 与 planning-event 核验，可以沿用该思路。初始状态计时还应注明是初始 history padding；若报告稳态 MPC 成本，需另取预先固定的真实历史快照。

只比较一次规划延迟会偏向频繁重规划方法。纳入不同执行长度后，应同时报告规划延迟、规划延迟/执行步数、每 episode 实际规划次数与累计规划时间。单位执行步成本是摊销指标，不能当成控制调用 deadline。

LeWM/CEM 只有 300×30 一个预算，不能证明同时间预算下 CoWM 更优。少量开发阶段预算候选（例如 64×5、128×10、300×30）及正式锁定的成功率—延迟比较应放入专门预算实验，并由本计划链接；不必把所有预算与整个 GF/PO 网格交叉。

### G. GF/PO “相同更新数”不等于相同计算或相同总位移

轻量 PO2 与 GF 两步各一次虽然都是两次 B 更新，GF 还调用 A 并通过 clean-action estimate 反传；较大档是 PO5 对 GF10。当前 GF 每个 Euler 步重置局部 reference，PO reference 是完整生成结果，`max_rms_offset=0.2` 的约束意义也不同。

应写明总更新数、A/B 前向／反向次数、reference 定义和裁剪后的实际动作位移。两档分别叫 PO2/GF2、PO5/GF10 更直观；两档均不宣称等计算预算。正式速度对比以完整调用实测为准。

### H. 论文模板与正式计划尚未一致

`paper/sec/4_experiments.tex:11` 和 `paper/tables/final_main.tex` 仍包含 DeWM；主表模板已有 P0、同 A+LeWM，而正式计划只展示四行。实验章还声明公共动作边界与训练 seed 层级的配对区间，计划目前是差异化裁剪、单训练 checkpoint 和 eval-seed std。

正式执行前应以最终计划同步正文、主表模板和 `paper/docs/MAIN_TABLE_PROTOCOL.md`。Table 1 对固定系统性能负责，完整训练耦合归因由另一个有明确范围的消融计划负责；没有对应证据的机制收益应继续收窄主张。统一 25/50 应描述为本研究重评协议，避免把代码默认和每篇原论文的表格设置混为一谈。

## 3. 哪些内容值得加入正式方法／主表

| 内容 | 建议位置 | 依据与限制 |
|---|---|---|
| CoWM P3，S=2、N=64 | 保留主方法候选 | Phase1.6 有局部选择信号和低延迟；不写一般排序优势 |
| CoWM P0 | 建议主表增加，或紧邻消融表展示 | 同权重最低成本参照，也直接解释 PO2 的增量 |
| 同 CoWM-A + LeWM，P3 | 优先增加主表／正式核心对照 | Phase1.7 说明质量优势不稳定；需要展示评分质量与速度取舍 |
| Random-64 | 正式核心消融；主表有空间可列 | 控制候选生成分布，避免把 actor 质量归功于 B |
| Reacher 短 execute/score | 值得开发桥接后冻结为时域候选 | 10/10、5/5 均有强探索信号；需要 clip 桥接并给 baseline 同等机会 |
| P0-PO2 | 保留已命名的 Refinement 版本 | 闭环增益区间跨零；与 P0 并列，不预设一定更优 |
| P3 先选后 PO | 保留次要推理消融 | 修复最终裁剪后评测；当前不够证据替换默认 P3 |
| GF 或大更新预算 | 保留次要推理消融 | 更昂贵，当前无稳定跨任务增益 |
| 在线 rank_1.0 | 单独的数据设定／补充实验 | 新增真实分支数据，且对原 Joint 的闭环增益未确证 |
| 新 1×25、5×1、1×5、1×1 | 待本轮闭环选择结果 | 训练尚未齐备，不能从 loss 或现有短前缀结果推断 |
| Recorded-control / B-only | 训练／评分器消融 | 最终结果未建立稳定优势，尚无理由替换完整四任务主模型 |

保持当前命名时，建议主表至少包含 LeWM、LeFlow、CoWM-P0、CoWM-Selection、CoWM-Refinement、同 A+LeWM；第二阶段接入 Sub-JEPA。Random-64 可以放紧邻的消融表。短时域应表现为明确的 operating point 或单独时域结果，不需要把每个组合都命名成新方法。

## 4. 建议的最小收口顺序

1. 修复／冻结裁剪与 guidance 语义、完整重规划计时、最终显存与实际动作记录。
2. 加入同 A+LeWM、Random-64；明确 PO 对 P0 的直接比较。准备归档与公共样本可以继续。
3. 以已完成 Phase5 为依据做有限开发桥接，给三个系统同等时域机会；对正在训练的结构保留待决状态，直到有闭环比较。
4. 冻结最终权重、每任务时域、baseline 设置、主要比较、统计规则和代码版本，再运行正式成功率。
5. 原计划的大推理矩阵与无裁剪对照随后运行；新增条件重新计算总量，不继续沿用 912 的固定验收数。
6. 同步论文正文和表格。将正式固定模型主表、训练消融及预算实验各自能够支持的主张写清楚。

本次只进行文件、原始结果和运行状态复查，新增本报告；未修改实验计划或实现，未启动训练、评测或测试。
